# 0.7.0：新規タブの位置とタブの閲覧順

## 新しいタブの位置

- リンクの「新しいタブで開く」、target=_blank、ポップアップは、元のタブのすぐ右隣へ追加する。バックグラウンドのタブから開いた場合も、その元タブを基準にする。
- メニューの「新しいタブ」「新しいプライベートタブ」等も、操作していたタブの右隣へ追加する。
- 通常のツールバー、アドレスバー左右に置いた＋、タブ一覧下部の＋は、従来どおり全タブの末尾へ追加する。
- アドレスバーを末尾から次へスワイプした場合の新規作成も末尾のまま。
- タブ上限500、既存タブの順序、画像キャッシュの扱いは維持する。再起動時の復元は保存された順序どおりで、復元時に並べ替えない。

## 見ていたタブへ戻る／進む

設定の「ツールバーのボタン」→「ボタンを追加」で次の2つを選べる。アドレスバー左右のボタン編集でも選択可能。既存の初期配置には自動追加しない。

- **前に見ていたタブ**：タブを表示した順序を1つ戻る。
- **後に見ていたタブ**：戻った順序を1つ進む。

ページ内の戻る／進むとは独立している。例えばA→B→Cの順に見た場合、戻るでC→B→A、進むでA→B→Cと移動する。戻る／進む自体を新しい閲覧として追加しないため、直前の2タブを往復するだけにはならない。戻った後に別のタブを選ぶと、その位置から新しい順序になる。

閉じたタブは順序から除外し、移動先がない時はボタンを無効にする。閲覧順は起動中の直近4096回までで、通常・プライベートともディスクに保存しない。再起動後は復元された現在のタブから記録を始める。通常タブのURL・順序の復元や履歴一覧の保存は従来どおり。

## 旧版との互換性

新しいボタン名を従来のtoolbar.jsonへ直接書くと、旧版のenumデコーダーが読めなくなる。そのためtoolbar.jsonには旧版が理解できるボタンのみを書き、完全な配置をtoolbar-extensions.jsonへ保存する。

旧版へ戻したままツールバーを編集した場合は、次の新版起動時もその最新編集を優先する。旧版で編集していなければ、新版用の配置を再び読み込む。旧版が新しいボタンを表示できない場合も、ブックマーク・お気に入り等の保存を止めない構成とする。

Bundle ID、browser.jsonのschema1、ブックマーク・お気に入り・履歴、広告フィルター、アイコンキャッシュ、build14の再生制御は変更しない。

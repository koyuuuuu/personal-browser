# 0.10.0 音源別の音量・ミュート

メニュー →「音声ミキサー」で、既に開いているタブのDOM上の音声・動画をタブ別に表示します。音源ごとのミュートと、対応する音源の0〜100%の相対音量を操作できます。検出だけで再生経路を変更したり、休止タブのWebViewを生成したりしません。同時再生の設定は従来どおり「設定 → 音声の同時再生」にあります。

音量制御の有効化は音源ごとに任意です。「音量調整を有効にする」を選ぶと元のタブへ移動し、ページ上の確認ボタンを押した場合だけ、その音源をCORS付きで読み直します。一時停止や再生位置のずれが起こる場合があります。ユーザー操作で作った専用AudioContextへ、CORS読込成功後に限りMediaElementAudioSourceNode → GainNodeを接続します。CORS失敗時はSourceNodeを作らず元の読込属性へ戻し、再生はユーザーに委ねます。単なるHEADチェックやURLの同一オリジン判定では、リダイレクト等による無音化を避けられないため使用していません。

音量は選択した音源だけに適用し、GainNodeの変更を短く平滑化します。100%に戻してもWeb Audioの接続は解除されません。元のネイティブ再生経路に戻すにはミキサーの「元の再生方式に戻す（ページ再読込）」で確認して再読込してください。ページの未送信の入力・再生は中断されることがあります。音量・ミュート制御は文書の寿命内のみで、アプリ再起動後の自動適用は行いません。

対応範囲は直接のHTTP(S)音声・動画ファイル（mp3/wav/m4a/aac/ogg/oga/mp4/m4v/webm）です。メタデータの未読込、ライブ、Blob/MSE、DRM、srcObject/通話は音量調整の対象外です。全画面・PiPでは有効化せず、インラインへ戻してから操作します。YouTubeの一般的なMSE再生は個別ミュートのみです。DOMに露出しないWeb Audioやネイティブプレーヤーは検出できません。他アプリやApple Musicの個別音量を操作する公開APIは使用できません。バックグラウンド・PiP・サイトの排他制御への制限は残ります。

スクリプトは隔離されたdefaultClientワールドで全フレームに注入し、実際のWKFrameInfoへ固定コマンドを送ります。ソースURL・Cookie・選択文字列・音声データを記録せず、音源の短いラベルと状態のみメモリに保持します。AudioContext/play/pauseの上書き、停止後の強制再生、再開ループはありません。既存のbuild14メディア処理、0.9の同時再生設定、バンドルID、schema1、WebKitデータストアと全保存済みデータを維持します。追加Entitlementはありません。

検証は既存Python・Core・デバイスビルドに加え、関連するネイティブUIシナリオ1本のみです。実PCMの2音源で個別ミュート・CORS確認・独立したGainNodeパラメータ・解除を確認し、別オリジンのCORS拒否で無理にWeb Audioへ接続しないことを確認します。スピーカーの波形、iPhone上の全サイト、YouTube/PiP/Apple Musicとの全組合せを確認したという意味ではありません。

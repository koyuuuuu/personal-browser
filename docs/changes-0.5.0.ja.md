# 0.5.0

利用者が現行版を良好と確認したため、0.4.2 build27を復帰先として保持し、機能追加版を0.5.0に上げる。Bundle ID、schema 1、WebKit保存領域、PiP/音声のbuild14方針は維持する。

- お気に入りのホームアイコンを長押しして別のアイコンへ重ねると順序を変更。設定に編集・追加・削除・並べ替え画面を追加。
- ブラウザで開く明示操作はサイトごとにブラウザ優先を記憶。対応アプリで開くと再びアプリ優先。iOS全体のUniversal Links設定を変える公開APIはないため、アプリ内の選択として実装。
- WKWebViewの通常リンクを公開load APIで開き、引き渡し時の既知の中断と本当の失敗を区別。予期しないWebKit 102はGET/HEADのみ一度再試行。POSTやダウンロードは再送しない。Safari互換の識別子をWKWebViewの既定UAに補う。Xの認証済み実機ページの成功を自動試験で保証するものではない。
- Google/Bing/DuckDuckGoの検索結果では検索語をアドレスバーに表示。同じエンジンで編集・再検索。通常ページはURL表示。
- アドレスバースワイプの高頻度更新をプレビューだけに分離。操作開始時のスナップショット処理を除き、画像を一度だけ取得。隙間4pt、不透明なタブ一覧と同じ背景色。プラス操作では水平スライドしない。
- `mybrowser://open?url=`を受信し、新規タブで開く。手順はshortcuts.ja.md。
- ホームで入力中に選択中エンジンの検索候補を最大6件表示。設定で切替、初期オフ、プライベートでは送信しない。350ms待機・変更時キャンセル・5秒タイムアウト。Cookie/永続キャッシュを使わない。各提供元の無料公開エンドポイントを利用し、応答変更・障害・レート制限時は候補なしで通常検索を続けられる。

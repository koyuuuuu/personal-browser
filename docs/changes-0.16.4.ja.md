# 0.16.4 PiPから画面をロックした時の再生継続

非排他モードのambientをPiPにも適用していた一方、通常の背景再生補助はOSが管理するPiPを対象から除外していた。そのため、PiPの再生用カテゴリを保持できず、ロックで再生を妨げる経路が残っていた。PiP開始時と非アクティブへの移行時にplaybackを保持し、ロック中にPiPの表示モードが一時的にinlineと通知されても解除しない。通常の前面表示へ戻り、PiPを終了した時だけ保存済みのambient／autoへ戻す。背景再生設定がオフでもPiPは独立して保護する。

BrowserTabに既存の全フレーム集約PiP状態があるため、そのPublished値をAudioMixingControllerで監視する。メイン文書では公開のPiPイベントも直ちに確認する。ネイティブから設定値・PiP所有権・前面状態を既存の公開Objective-Cブリッジで渡す。PiPとロックへの移行ではカテゴリを設定するだけで、停止したメディアを再生・音量変更・PiP終了・読み込み直し・別プレーヤーへの置換を行わない。既存の録音優先と手動停止、ミュート、割り込み、経路変更、通常背景復帰の1回・3秒制限を維持する。build14のupdateMedia/mediaScriptはバイト単位で同一。

全画面からPiPへの移行後は、全画面アダプターの状態やCSSラッパーだけを解除する。PiP開始イベントを受けた場合と、モードだけがPiPになりイベントが遅れた場合の両方で、webkitExitFullscreenを呼ばない。ページ離脱やdocument.exitFullscreenが来てもPiPそのものを終了しない。元の動画と再生状態は保持する。

通常の前面再生では0.16.3の他アプリとの同時再生設定を維持する。PiP・ロック中は再生継続を優先し、あらゆる他アプリとの背景同時再生を保証する機能ではない。パスワード警告や全画面バナーを再導入しない。

ローカル検証: Python63件、プロジェクト整合性、音声設定両値・PiP・非アクティブ・一時的なPiP表示消失・復帰・別オリジンからの集約・背景設定オフ・背景所有権解除・録音／停止／ミュート保持を確認。音声ポリシー検証はAPI状態を模擬し、play／exit呼出しがゼロであることを確認する。全画面検証は実ChromiumのPopoverと動画時計を使い、PiP移行後に元の動画を保持しつつラッパーだけ解除することを確認する。iOSのネイティブPiP呼出しは模擬であり、物理的なロック画面や音声出力の成功とは扱わない。

利用者の実機テストを自分で行うという直前の希望を引き継ぎ、長いiOS UI操作検証は実行しない。Release実機用ビルド、IPA検査、配信、公開取得確認のみを一時ワークフローで実行する。実機でのPiP→ロック→復帰と各サイトの受け入れは未確認として記録する。通常CIは変更しない。

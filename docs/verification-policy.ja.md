# 検証の実行条件

2026-10-26、本人が「必須・高のみ毎回、条件付きは該当時のみ、それ以外は通常検証から削除」と指示したことに基づく。過去の全件実行の記述より、この方針を優先する。方針変更時の配信アプリは0.5.0 build38。現在の最新版は[0.6.0 build42](changes-0.6.0.ja.md)。

## 毎回の基本経路

1. LinuxでPython検査。配信処理・IPA検査・プロジェクト整合性・検査対象選択を確認。プロジェクト検査を別途二重実行しない。
2. macOSでCoreテスト。URL、保存、取り込み、プライベート情報等の短い単体検査を維持する。
3. 実機用arm64 IPAを生成し、Bundle ID・OS・版番号・ハッシュを検査。通常のpushでは実施。手動のbuild_ipa=falseは従来どおりテストのみ。
4. アプリ本体・Core・リリース設定に変更がある場合のみ既存のRelease/SideStore配信へ進む。検証コード・CIだけの変更はIPAの生成までで、同じ機能を新版として再配信しない。
5. 配信した最新版を匿名取得し、配信JSONとの版番号・Bundle ID・サイズ・ハッシュを照合する。

文書だけの変更ではCIを起動しない。App/Coreの変更時には従来どおり先に次の版番号へ更新する。

## 条件付き検査

判定処理は`scripts/verification_plan.py`。push内の全コミットを比較し、手動実行では直近の配信タグから比較する。判定理由として変更ファイル・対象機能・選択したテストを`verification-plan`成果物へ1日保存する。

| 条件 | 実行する追加検査 |
|---|---|
| タブ一覧・選択・追加削除を変更 | 連続削除後の再配置・操作、アクティブタブの位置 |
| バー・縦横レイアウトを変更 | 横画面での切替後の操作・タイル幅、縦画面のスクロール判定 |
| ホーム・お気に入りを変更 | 背景付き横画面操作、ドラッグ・編集・再起動後の保持 |
| 履歴・ブックマーク・取り込みを変更 | ライブラリ操作・履歴の個別／半日削除・候補 |
| 設定やツールバー構成を変更 | 左右ボタン・タブ列数、倍率保存、広告設定の代表ケース |
| URL受信・リンク配送を変更 | 通常リンクとPOST、OS経由の未起動／バックグラウンド受信・不正URL拒否 |
| TLS判断・ローカル接続を変更 | 証明書例外の記憶有無、明示的なHTTP切替 |
| サムネイル保存を変更 | ページをロードせず再起動後に画像を保持 |
| 共有・更新通知・検索候補を変更 | 変更した機能の代表ケースのみ |
| モデル、保存形式、保存／復元、取り込み処理を変更 | 初期版と0.4.2を使った最新データの往復読み書き |
| 配信・IPA検査コード、履歴ID対応表、配信先や識別情報を変更 | 公開されている全IPAの匿名取得・ハッシュ検査 |

判定は主にファイル単位。多機能なBrowserStoreはメソッド単位で比較し、スクロール処理だけの変更でデータ互換性検査を動かさない。共有ファイルに複数機能が入っている場合は、そのファイルに対応する複数ケースを選ぶ。新しい画面や保存処理を追加する際は対応表も更新する。

## 通常経路から外したもの

- 全UIテストの一括実行。対象がなければシミュレータ・Webサーバー・証明書も準備しない。
- 単純なWAV再生をPiPの合否として扱う試験。該当するUIテスト本体も削除した。
- 重複する単発のタブ追加・スワイプ・バー復帰・設定切替ケース。過去のケースは参照用として残っていても自動選択しない。
- 通常の更新時の全旧IPA再ダウンロード。旧IPA・タグ・記録は削除せず、資産の存在とサイズを確認して継続配信する。
- プロジェクト整合性のLinux/macOSでの重複検査。
- テスト操作や環境の失敗に対する、無条件の全件再実行。

PiP、実サイトの動画、カクつきや見た目は、関連処理を変更した際に実機観察で確認する。UI要素の存在や単純音声の成功を、これらの動作保証として報告しない。

## 反映結果

[run38](https://github.com/koyuuuuu/personal-browser/actions/runs/40247759627)で新しい構成が成功。Python43件、macOS Core53件、実機用IPAの生成・検査が成功し、シミュレータは起動していない。保存処理に変更がないため互換性検査は実行しなかった。今回は配信処理を変更したため、条件に該当する全10版の公開IPA照合は実施した。アプリの再配信は行わず、SideStoreで利用中の0.5.0 build38を維持した。[機械可読の記録](validation-verification-policy-2026-10-26.json)。

アプリ変更後に検査の修正が続く場合は、配信済みタグから残っているアプリ領域の検査も維持する。直前のpushがテスト修正だけであっても、未解決の機能検査を落として配信しない。配信判定も直近の配信タグとの差分から行う。保管IPAの全件監査は従来どおり今回の配信・保管処理変更に該当する時のみ。

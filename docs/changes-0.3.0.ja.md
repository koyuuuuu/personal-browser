# 0.3.0の変更と使い方

2026-10-25（日本時間）。本体のソースは非公開、IPA・ソースJSON・アイコンのみ公開する方針を維持する。

## 実装した操作

| 要望 | 操作・実装 |
|---|---|
| PiPでホームへ戻ると映像が止まる | PiPの明示許可、バックグラウンド音声モード、再生時のAudio Session設定、WebViewを保持する表示面を実装。再生中・PiP中はタブを休止しない。実機での改善確認が必要 |
| 広告ブロック | 設定 → ブラウザ機能。初期値オン。既知の広告配信ドメインへの第三者リクエストをWebKitルールで遮断。サイト別の除外も可能 |
| 共有が空になる | 共有URLをシートの表示状態と一体に保持する方式に修正。iOSの共有シートを使用 |
| アドレスバーの左右スワイプ | 左で次のタブ、右で前のタブ。入力中は切り替えない。設定で無効化可能 |
| タブのタイル表示 | メニュー／タブボタンで2列のプレビュー。選択中の枠・プライベート表示・動画再生状態を区別 |
| 500タブ | 通常とプライベートを合わせて最大500。最初から500個のWebViewを作らず、選択時に読み込む |
| タブを左へスワイプして閉じる | タイルを左へ80ポイント以上スワイプ。閉じるボタンとアクセシビリティ操作も利用可能 |
| ホームのお気に入り | ブックマークと別に保存。小さなタイトルとドメインの頭文字アイコンをグリッド表示。長押しで編集・前後への移動・削除 |
| ホームの背景画像 | 設定 → ブラウザ機能 → 背景画像を選ぶ。列数は3～6列、背景の表示・削除も設定可能 |
| ブックマーク一覧 | 本のボタンから従来どおり行表示。検索、フォルダ作成、名前・URL編集、移動・並べ替えに対応 |
| ツールバーの位置・順序 | 設定の「バーの位置」、右上「編集」からボタンの追加・削除・並べ替え。プラス／共有ボタンも追加可能 |
| タブ追加のアニメーション | 追加時に短い通知を表示。設定とiOSの「視差効果を減らす」に従う |
| 他ブラウザから取り込み | 設定 → データの取り込み・書き出し。種類を選び、HTML・CSV・JSON、またはSafari ZIPを選択。プレビュー後に追加。重複URLは追加しない |
| パスワード | 本人の希望によりAppleのパスワード／iCloudキーチェーンを利用。独自保管庫は作らない。パスワードCSVはライブラリへ取り込まず、Safari ZIPのパスワードファイルも展開しない |
| リンク長押し | 現在／新規タブ、コピー、共有、Watch HTML、階層型の「アプリで開く」 |
| アプリで開く | YouTubeのリンクは対応アプリへ。Chrome・Firefox・Brave・Edgeは対応スキームを使用。リンクファイル保存、メール、メッセージ、共有先の選択も提供 |
| 日常機能の補完 | ページ内検索、タブ／ライブラリ検索、ファイルのダウンロードと共有・削除、JSON書き出し、直近20件の閉じたタブを戻す操作（端末内メモリのみ） |

## Watch HTML

本人が指定した自作ビデオサーバーの `/watch` を利用する。バックアップのwatch.htmlでは `url` クエリを読み、入力欄にセットして解析を開始することを確認した。ブラウザ側はURLComponentsで動画URLを1つのクエリ値として渡すため、動画URL内の `&` や日本語も壊さない。

メニューの「コピーしたリンクをWatch HTMLで解析」は、押した時だけクリップボードを読む。リンク長押しからも直接渡せる。接続先は設定 → ブラウザ機能へ保存する。すでに端末内の履歴に `/watch` または `/watch.html` があれば、未設定時はその履歴を再利用する。Watch HTMLをこのブラウザで開き、メニューの「このページをWatch HTMLの接続先にする」でも保存できる。

個人サーバーのホスト名・トンネルの認証情報を公開IPAの初期値や配信JSONへ含めない。サーバーへのログインは通常のWebページとして本人が行う。作業環境から現在のサーバーへのGETは403だったため、iPhoneでの実際の入力反映と解析開始は受け入れ確認が必要。

## SafariとAppleのパスワード

Safari側で書き出したファイルを選択する。iOS・地域・Safariの版によって書き出し項目が異なるため、iPhoneに書き出しがない場合、対応するPC側の書き出しを利用する。WindowsでSafariのブックマークを扱う場合は、iCloudのブックマーク同期に対応するブラウザを経由してHTMLを書き出す方法もある。Safariの履歴や他アプリの保管庫を、iOSのサンドボックスを越えて直接読み取る機能ではない。

Safariで使っているパスワードは同じApple Accountの「パスワード」アプリとiCloudキーチェーンを継続利用する。iOS 18では「設定 → 一般 → 自動入力とパスワード」で利用する管理機能を選ぶ。Webフォームで提供される自動入力／キーボードのパスワード選択を使う。Appleのパスワード保管庫へ第三者アプリが任意の項目を直接登録するAPIは使用していない。

## データとメモリ

従来のbrowser.jsonはschema 1のまま。お気に入り・フォルダの対応・追加設定は別ファイルに保存する。アップデートと機能の巻き戻しで、古いブックマーク／履歴へ戻す処理は入れない。

背景画像はImageIOで最初から最大1,800ピクセルに縮小し、巨大な写真をフルサイズで展開するメモリ消費を抑える。お気に入りのアイコンサイズも列数に合わせて調整する。

WebViewの保持数は初期値4、設定で2～8。非選択かつ非再生の古いページを休止し、必要になった時にURLから読み直す。フォーム入力やタブ内の戻る／進む履歴は、休止やアプリ再起動を越えて保存しない。動画／PiP再生中やダウンロード中は休止を避ける。プライベートなURL・履歴・プレビューをディスクへ保存しない。

0.2.0以前は12タブまでの版なので、その版へ戻すとセッションを12タブまでに制限する。ブックマークと履歴の互換性は別にテストする。500タブの全セッションを古い版で維持できるとは扱わない。

## 制約と次の候補

- 広告ブロックは小規模な内蔵ドメインルールで、Brave相当のリスト更新・高度な広告要素除去・YouTube動画広告除去は含まない。高度な外部リストは提供元・ライセンス・更新方法を選定してから追加する。
- iOSはインストール済みアプリを自由に列挙したり、特定の共有拡張を強制的に開いたりできない。メモ・ChatGPT・Claude等は共有シートに提供される項目から本人が選ぶ。各アプリのインストールと共有拡張の対応が必要。
- 「Safariの画面」はSFSafariViewControllerでSafari標準の画面を表示する。「既定のブラウザ」はOSのリンク処理に従い、Universal Linkに対応するアプリが優先される場合がある。
- プライベートタブからのファイルダウンロードはディスクに残さないため停止し、通常タブでの操作を案内する。手動保存したお気に入り・ブックマークは通常の保存データとして残る。
- 検証後も追加候補：タブグループ、リーダー表示、サイト別文字サイズ・PC表示、実サイトのfavicon取得とキャッシュ、追跡防止リストの定期更新、バックアップの暗号化、ダウンロードの進捗・再開。

# 0.16.2 消音中の再生と全画面操作

非排他モードがWeb Audio Sessionをambientへ切り替え、ホーム／コントロールセンターから戻る際にもその値を復元していた。ambientは消音スイッチに従うため、今回の「どちらの設定でも消音中に再生」の要望と両立しない。前面のWeb音声はambientを強制せずautoでWebKitに実際のメディア・録音を判定させ、ネイティブはplayback + mixWithOthersを毎回準備する。背景移行中だけは既存の補助が一時的にWebのplaybackを所有し、前面の状態イベントはその所有権を解除しない。設定変更・実際の再生開始・前面への復帰・ページ再表示・音声セッション状態変化で方針を適用する。設定値は従来の独立キーを保持し、同時再生は可能な範囲で試みるが、消音中の再生を優先する。

バックグラウンド補助は古いambientを復元せず、現在の前面ポリシーへ戻す。録音／通話のrecord・playAndRecordは優先し、サイトのミュート・音量ゼロ・一時停止は変更しない。設定や前面への復帰で音源を強制再生したり音声セッションを停止したりしない。既存の1回・3秒の背景復帰予算、手動停止／通話／イヤホン切断の取消しは保持する。build14のupdateMedia/mediaScriptはそのまま。

標準のElement Fullscreen APIはWKPreferencesの初期値falseのままだった。通常タブ・埋め込みプレーヤー・補助ウィンドウにも公開APIのisElementFullscreenEnabledを設定する。ユーザー操作やiframeのPermissions Policyは維持する。動画専用のwebkitEnterFullscreenだけでなく、サイトがプレーヤー全体に使うrequestFullscreen／exitFullscreenを利用できるようにする。

WebKitは標準全画面中にWebViewをプレースホルダーと置換し、専用ウィンドウへ移す。アプリの一覧用コンテナがその最中に通常の表示領域や変形を適用しないよう、公開fullscreenStateと実際の親ビューを確認する。公開KVOで終了を監視し、WebKitが返した後に通常領域を復元する。アプリ側でWebViewを奪い返したり再生成したりしない。通常時も同じ幾何情報を書き直さず、標準プレーヤーの遷移を妨げない。

ローカルの音声ポリシー検証はAudioSessionの型だけを模擬し、設定両値・前面復帰イベント・背景復元・録音・一時停止・ミュート保持を確認する。Chromiumでは実動画の標準全画面への移行と終了を通常ページ／別オリジンiframeで各2回確認する。これらをiOSでの消音スイッチや音声出力の実証とは扱わない。

iOS検証は4設定の実際のコントロールセンター往復とネイティブ／Web再生モード・実音源の時計、従来の複数タブ同時再生、実際のOSホームと動画時計、標準全画面の繰り返し移行／終了と回転／同じ動画の保持、従来の自動全画面／縦長動画、タブ一覧の連続遷移／回転／削除、通常ページ操作／パスワードを対象とする。診断と起動時の固定ページはDEBUG＋各2フラグ限定で、製品版の領域を予約しない。保存形式・TLS・旧アーカイブを変更しないため、それらの追加往復検証は行わない。

実際のiPhoneの消音スイッチ・スピーカー出力・特定の第三者サイトの受け入れは別途必要。サイト自身の停止やDRM、WebKit／他アプリの排他制御を解除する機能ではない。

初回iOS検証105ではCore85件は通過したが、OSホーム中の元動画の時計が18.36秒に対して0.10秒しか進まず、背景継続を満たさなかった。再生は明示的な停止状態ではなかった。この時点では埋め込み文書の違いを疑い、各文書にも方針を試みるよう修正。型だけを模擬したポリシー検証にも別オリジンiframeを追加し、背景テストにはDEBUG＋既存2フラグ限定の短い方針・復帰診断を追加した。背景時計の成功条件は緩和しない。WebKitの実装では型はページで共有され、別オリジン文書ではMicrophone Permissions Policyにより設定が拒否されautoと見える場合があるため、このautoだけから原因は断定しない。残りのUI・製品版ビルド・配信は105では未実施。

検証106はCore85件と最初の実OSホームでの動画時計進行を通過。次の明示停止後のホームでは、時計は0.00秒・paused=trueを維持したが、8秒のOS待機に対して非表示通知間隔が5.42秒しかなく、必須の6秒以上を満たさなかった。停止の判定を緩めず、この待機も最初と同じ12秒に変更する。非表示の信頼された通知対・6秒以上・停止時計差0.75秒未満の条件は保持する。106も残りのUI・配信へは進んでいない。

検証107はCore85件を通過したが、最初のホームで時計0.02秒／6.93秒・paused=falseとなり、106の進行成功だけでは背景継続の安定性を確認できなかった。常時のWeb playback固定を廃止し、前面はauto、ネイティブは消音に従わないplayback + mixWithOthersを再適用する。既存の背景移行だけが一時的なWeb playbackを所有し、前面へ戻る際は所有フラグを先に解除してautoへ戻す。録音開始に不適切な常時exclusive型の指定も避ける。新たに報告されたControl Center／標準全画面の2ケースを先に実行し、その後にHomeと残りの関連ケースを必須とする。全9件の判定条件・1回3秒の復帰予算は保持する。

検証108は、埋め込み文書の状態イベントがページ共通の背景playbackをautoへ戻し得る経路をソース確認で見つけ、配信前に中止。型の更新は上位ページだけが所有し、子フレームの再生通知はネイティブ経由で上位へ渡す。トップの所有フラグを確認してから更新するため、背景の所有権を子が解除しない。停止済み要素の合成playイベントでは音声セッションを有効化しない。ポリシー検証に子フレームの直接更新を拒否する条件を追加した。

検証109はCore85件と標準全画面174.331秒を通過。実iOSで通常文書と別オリジンiframeの標準APIによる表示／終了を各2回、回転・時計進行・元動画と通常タブ操作の保持まで確認した。音声ケースは最初の設定スイッチをオンにできず、再生開始／Control Center操作より前に停止。実際の画面ではスイッチは可視だがオフのままで、原因を音声再生失敗とは扱わない。SwiftUI行ラッパーの座標タップをネイティブUISwitchのつまみ操作＋設定値の待機検証へ変更する。DEBUG診断の同値再通知も抑え、Swift6のKVO警告は新値だけをMainActorへ渡して修正。残りの8件・Release・配信は109では未完了。

検証110はCore85件と標準全画面203.646秒を再度通過したが、音声ケースは起動直後の最初のAXスナップショット取得でタイムアウト。終了時の階層にはアドレス欄があり、ページは読み込み初期状態だったため、設定操作や音声の結果ではない。無音の画面表示・設定切替ではAVAudioSessionを準備せず、実際の非ミュート再生と活動中のWeb Audio、前面復帰時の実playing判定で準備する。診断も初回再生前にはAVAudioSessionを読まない。テストの音声ページはBOTH flags限定のネイティブ準備ボタンで初期UIの後に開く。PCMは明示再生までプリロードせず、停止中の同じ時計文字列を繰り返しDOMへ書かない。OS操作・実時計・全9件の条件は保持する。

検証111はCore85件通過。音声は準備ボタンの実タッチ後、初回ページ待ちで停止し、画面はWK読み込み10%・方針待機のまま。再生／コントロールセンター未実施。標準全画面は4回の実移行・回転・時計・終了確認後、タブ一覧のAX取得で停止し、終了時の階層には実際の一覧・カード・完了が存在した。どちらもケース全体の成功とは扱わない。音声方針は据え置き、固定ページへのHTTP接続確認と固定ルートの到達ログを追加し、画面探索をfirstMatch・一意の画面内コントロールへ限定する。読み込み済み音声ページの不要な再読み込みを削除。実OS操作・時計・全9件の条件と待機上限は保持する。111で配信なし。

検証112はCore85件と標準全画面214.201秒を通過し、通常のタブ操作まで成功。音声は再生前で停止。RunnerのHTTP確認17:22:40は成功したが、準備ボタン17:23:13から実際のWK要求17:24:41まで約88秒かかり、AX待機の失敗後に届いた。音声不良やサーバー停止の証拠ではない。固定ルートの実WK要求数を取得し、初回はAXを呼ばず実HTTP到達を最大120秒待ってから、従来どおり表示60秒・実再生・OS操作を確認する。模擬読み込み完了や自動再生の解除は行わない。ローカルの実HTTPで事前確認は数えずWK要求のみ数えることを確認。失敗しても残りの選択済みDebug・Release結果を集めるが、1件でも失敗すれば製品ビルド・配信を止める。全9件は必須のまま。音声・全画面の本体方針は変更せず、112では配信なし。

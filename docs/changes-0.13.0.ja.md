# 0.13.0 キーボード直上の入力候補と保存・更新提案

ログイン欄を選ぶと、ブラウザの保管庫に保存したアカウントをキーボード直上の1行候補から入力できるようにする。入力のために保管庫の管理画面へ移動しない。

## 使い方

- 解除中: 候補のアカウントを押すとユーザー名・パスワードを入力する。
- ロック中: 「保存済みパスワードを入力」から端末認証を行う。一致が1件なら入力し、複数ならバーで選ぶ。ロック中は保存件数や名前を読み出さないため、この汎用ボタンが保存済み項目の存在を意味するわけではない。
- 保存情報なし: 登録の入口を表示する。既存データの取り込み・編集・暗号化バックアップはメニューの「パスワード」から利用できる。
- Apple標準のパスワード候補は、Webの入力欄を選んでiOSのキーボード上で利用する。以前の「Appleのパスワード」は候補そのものではなくフォーカス移動のボタンだったため、独自の候補バーから外した。Appleの保存内容の直接読み出しや認証省略は行わない。

下部ツールバーは対応するログイン欄のソフトウェアキーボード表示中に一時的に退避し、候補とキーボードの間に挟まない。ツールバー設定を保存し直すことはない。公開UIKeyboardLayoutGuideで表示を観測し、キーボード回避はSwiftUIだけが担当する。WebViewは作り直さず、Face IDの一時的なinactive中もレイアウトを維持する。

## 新しいパスワードの保存・更新

利用者がログイン・新規登録・パスワード変更フォームを送信すると、保存・更新を提案する。文字入力のたびには値を収集しない。初期オンで、「パスワード → 送信時にパスワードの保存・更新を提案」から停止できる。

- 同じサイト・ユーザー名がない場合は「保存」。
- 同じアカウントでパスワードが異なる場合は「更新」。既存のID・タイトル・メモを維持し、パスワードだけを変更する。
- 解除中に保存内容が同じと判定できれば新しい提案は出さない。ロック中は確認の入口を表示し、認証後に同じ内容と分かれば提案を閉じる。
- 新しいパスワードと確認欄が異なる場合や、無効なフォームでは提案しない。
- 変更フォームにユーザー名がなく既存の候補が複数ある場合は、更新するアカウントを選ぶ。1件の場合も更新先のアカウント名を表示して確認できる。
- ロック中の保存候補は、ボタンで認証してから保存内容を確認し、「保存」「更新」で確定する。認証だけでは既存データを置き換えない。

フォーム送信を観測しても、サイト側のログイン・登録・変更の成功までは分からない。提案は「送信した内容の保存」であり、成功を確認してから確定する。「今回はしない」で破棄できる。提案はメモリ上だけに最長120秒保持し、バックグラウンド・ロック・タブ変更・別サイトへの移動・期限切れで破棄する。確認前のパスワードをファイルやログに出力しない。

標準フォームの送信、Enterでの送信、submitボタンを使うAJAXフォームを対象とする。独自のdivボタン・閉じたShadow DOM等、すべてのサイトでの自動検出を保証するものではない。検出できない場合は従来の明示的な確認・保存を利用できる。

## 保持する条件

- 信頼できるHTTPSと完全一致するサイト・ポート、選択中の前面タブだけで入力・提案を行う。
- HTTP、証明書に問題があるページ、別サイトの送信先、別サイトのiframeには入力・保存しない。
- プライベートタブでは保存提案の収集をページ側から無効にする。既存項目の明示的な入力は従来の許可設定に従う。
- 自動ログイン送信は行わない。既存の「解除中は確認なしで自動入力」は別設定のままで、今回の候補入力に有効化は不要。
- 既存の暗号化保管庫・鍵・バックアップ形式、アプリID、ブックマーク・履歴・Cookieを変更しない。
- 自動ロックは従来の30/60/300秒設定で、初期値60秒を維持する。

## 検証範囲

Coreの保存判定・UTF8一致・更新メタデータ保持、実DOMの送信検出と入力中非収集、代表保管庫UI、Release構成のページ/キーボード操作を確認する。ネイティブテストのダミー認証やループバック信頼例外はDEBUG+専用フラグだけで、配布版へ入れない。CI結果は別の配信記録に残す。実際のFace ID、Appleの保存候補、利用者のiPhoneでの操作結果はCIと区別する。

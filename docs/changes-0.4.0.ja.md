# 0.4.0の変更と使い方

2026-10-25（日本時間）。従来のアプリID、schema 1のブックマーク・履歴、非公開ソースと公開IPA配布の構成を維持する。

## バーと表示

- 横画面へ切り替えると、アドレスバーとツールバーを最初は隠す。ページの上側へ戻るスクロールで、画面上部に1行のバーを表示する。ページの下側へ読み進めると再び隠す。
- 横画面のバーは約40ポイント。アドレス欄と操作ボタンを横一列に並べる。ステータスバーも横画面では隠す。
- 縦横どちらでも、アドレス欄の横のボタンでバーを隠せる。隠れた時は小さな矢印ボタンから戻せる。縦画面は上／下の位置設定を維持する。
- 「設定 → 表示・操作」で、タブ一覧を1～4列に変更できる。
- アプリ内の文字サイズと、ページの文字・表示倍率（75～200％）を別々に設定できる。WebKitのページ倍率は文字だけでなく画像とレイアウトも拡大する。
- アドレス欄の左右は別々にボタンを追加・削除・並べ替えできる。従来の操作に加え、ホーム、履歴、ページ内検索、ダウンロード、Watch HTML、登録操作、設定も選択できる。編集から並び順を変更する。設定しない場合、横画面では従来のツールバーボタンを左右に振り分ける。個別設定をオンにすると、縦画面にも左右のボタンを置ける。
- ボタンを増やすとアドレス欄が狭くなる。最小幅を確保した後は左右のボタン欄を横スクロールできる。下段ツールバーの配置設定とは独立している。

## ホームインジケータ

標準のpersistentSystemOverlays APIで、自動非表示をiOSへ要求する。初期値は非表示優先。設定で戻すこともできる。下部の安全領域も閲覧画面では広く利用する。

iOS自身がジェスチャー時などに出す表示を、アプリが完全に禁止したり秒数を短縮したりする公開APIはない。常時消灯や一時表示のゼロ秒化を保証する機能ではない。

## タブと画像

通常タブのプレビューをApplication Support/PersonalBrowser/tab-previewsへ保存する。Library/Cachesや一時フォルダは使わず、有効期限を設けない。アプリ再起動後も、保存した最後の画像とタイトルを一覧に表示する。画像を見るために裏で全ページをロードしない。

ページの読み込み後、スクロールが止まった時、別タブへ移る時、バックグラウンドへ入る時に画像取得を試みる。取得が失敗した場合は最後に成功した画像を維持する。PiP中やDRM動画等では現在の動画フレームを取得できない場合がある。通常タブの画像はそのタブを明示的に閉じると削除する。プライベートタブの画像は引き続きメモリ内だけで、端末へ保存しない。

タブ一覧はアクティブなタブの位置へスクロールして開く。末尾のタブなら最下部で開く。＋ボタンは下部へ移し、通常のタップで新規タブを直接開く。下部メニューから通常／プライベート、閉じたタブの復元、全タブを閉じる操作もできる。

左スワイプの削除は、移動・フェード・周囲のタイルの詰め直しをアニメーションする。閉じたタブの選択処理が後から走らないようにしている。アドレス欄を次方向へスワイプした時、現在が末尾なら新規タブを作る。上限500では作らない。前方向で先頭を超える時は移動しない。

新規作成とタブ移動は短いスライド表示に変更し、「タブを追加しました」の通知は使わない。WebViewの同一性を保ち、再生中のページをアニメーションのために再生成しない。アニメーションをオフにした場合とiOSの視差効果を減らす設定に従う。

## 背景の位置とズーム

「ブラウザ機能 → ホーム画面 → 背景の位置・ズームを調整」、または「表示・操作」から変更する。縦横のプレビュー、100～300％のズーム、左右・上下の位置を調整できる。画面に合わせた切り抜きで、元の画像を破壊しない。中央へ戻す操作も用意する。

表示設定はpresentation.jsonに分離した。0.3.0以前の設定書き込みで、この追加ファイルを消さない。

## バックグラウンド音声

初期値で、PiPを使わない音声の継続を優先する。再生開始時にAVAudioSessionのplaybackを使用し、audioのバックグラウンドモードを維持する。再生面を保持し、バックグラウンドへ入った時にページを再読み込みしない。直前まで再生していたページは、バックグラウンド中の休止対象から外す。

「表示・操作」で無効にできる。アプリが停止した再生だけを復帰時に解除し、本人が一時停止した音声を勝手に再開しない。ミュート・音量0の自動動画で他の音楽を中断しないよう、音声が有効な再生を区別する。音声信号そのものの無音判定は行わない。

サイト自身のvisibility処理、WebKit、DRM、ネットワーク、iOSによる終了等の制約は残る。ローカルの制御された音声ページでバックグラウンド動作を検査し、日常の動画サイトはiPhoneで確認する。

## ローカル接続と証明書

192.168.1.120:3000のように、HTTPSが使えないローカルツールを区別して扱う。

1. 証明書が検証できないHTTPSは、接続先と証明書のSHA-256を示して確認する。キャンセルも選べる。
2. 「この接続先では今後確認しない」は初期値オフ。接続時にチェックした場合だけ、接続先・ポート・同じ証明書への検証例外を保存する。別の証明書に例外を自動適用しない。通常の検証に成功する証明書は通常どおり接続する。
3. 証明書の確認では解決できないTLS失敗で、相手がローカル接続先の場合は、HTTPで開く確認を提示する。HTTPの通信は暗号化されないことを表示する。
4. HTTPの確認でもチェックした場合だけ、その接続先を次回からHTTPで開く。インターネット上の一般サイトを自動的にHTTPへ落とす機能ではない。
5. 保存した例外は「表示・操作」から削除できる。削除しても既存の接続を強制的に切断せず、次回の接続確認から適用する。

全サイトのTLS検証を無効化したり、証明書をシステム全体の信頼ストアへ追加したりはしない。例外は端末内のsecurity-exceptions.jsonに保存する。閲覧データや接続例外を公開配信先へ送らない。

初回のローカル通信ではiOSが「ローカルネットワーク」の許可を求める場合がある。接続先が起動していること、同じネットワークから到達できることも必要。クラウドCIから本人のLANへ接続した検証とは区別する。


## iPhoneでの確認

SideStoreで既存アプリを削除せず、新版へ上書きする。更新前に登録済みのお気に入り・ブックマーク・履歴のいずれかを覚えておき、更新後も残ることを確認する。

- 自宅のWi-Fiで`192.168.1.120:3000`を開き、ローカルネットワークの利用を求められた場合は許可する。HTTPの確認なら説明を読んで開く。チェックなしでは永続保存せず、チェックありなら次回の同じ接続先に反映する。
- 日常の音声サイトで再生し、PiPを使わずホームへ戻して継続を確認する。サイトが自ら止める場合は、そのサイト名と発生条件を次の調査材料にする。
- 横画面にしてバーが隠れること、上側へ戻るスクロールで1行だけ出ること、小さな矢印で復帰できることを確認する。
- ページをスクロールして別タブへ移り、アプリを終了・再起動してタブ画像が残ることを確認する。

CIでは制御されたローカルのHTTP・自己署名HTTPS・音声ページを使う。本人のLAN、実サイトのDRM、iPhoneのOSジェスチャーの動作をCI成功だけで確認済みとはしない。

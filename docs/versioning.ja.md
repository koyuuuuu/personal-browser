# バージョン管理と旧版へ戻す手順

2026-10-24。非公開の`koyuuuuu/personal-browser`で管理する。

## 保存するもの

| 項目 | 保存方法 |
|---|---|
| 日々の変更 | Gitコミット。過去の変更履歴を残す |
| 利用に渡す版 | `v0.1.0`等のタグを、検証したソースのコミットへ固定 |
| 実際のインストール用ファイル | 未署名IPA・ビルド記録・SHA-256を版ごとに保管 |
| 変更内容と制約 | 非公開GitHub Releaseの説明文 |
| iPhone内のデータ | ソース履歴とは別。形式変更時にバックアップ・移行方法を実装・検証 |

現在の版は[v0.1.0 / build 6](https://github.com/koyuuuuu/personal-browser/releases/tag/v0.1.0)。タグのビルド元は`438292f5622801bf56525381576b789f65e4d203`、保存形式はschema 1。2026-10-24に本人がiPhoneで利用できたと報告した。

## IPAの保管先

現在のGitHub連携では、通常のリポジトリAPIが使えても`uploads.github.com`へのRelease assetアップロードが401になる。そのため[非公開のipa-archiveブランチ](https://github.com/koyuuuuu/personal-browser/tree/ipa-archive/v0.1.0)をIPA保管専用に使う。ソース用のmainとは分け、保管ブランチをmainへマージしない。

`v0.1.0/`に`PersonalBrowser.ipa`、`build-info.json`、`SHA256SUMS.txt`、説明を保存した。初期IPAは330,871 bytesと小さいため通常のGit blobで保存する。履歴は上書きせず、将来容量が増える場合は別の無料保管方法かRelease assetの利用可否を再評価する。Git LFSや有料ストレージを自動追加しない。

Actions成果物は一時保管として1日で失効するが、この保管ブランチにはその自動削除期限はない。リポジトリ・ブランチ等を削除しない限り保存できる。公開範囲は非公開のまま。秘密鍵、Apple Account認証情報、端末内の履歴・Cookieは保存しない。

## 今後の版の付け方

- 修正中心なら`0.1.1`等、機能追加なら`0.2.0`等へ更新する。
- ユーザー向けバージョンは`MARKETING_VERSION`、ビルド番号はCIの実行番号で区別する。ソースの毎コミットが新しい配布版になるわけではない。
- 検証に成功したIPAについて、版番号・ビルド番号・ソースSHA・CI実行ID・IPAハッシュ・保存データ形式を対応付ける。
- 過去のタグを別コミットへ動かしたり、同じ版のIPAを差し替えたりしない。
- Codexがコミット・検証・IPA取得・版の保管を進める。ユーザーは新しいIPAをSideStoreで上書きし、実機で確認する。

## 戻す場合

1. ユーザーが「0.1.0へ戻したい」等と指定する。
2. Codexが該当タグとIPAハッシュを確認し、保存済みのIPAを取得する。IPAが保持されていれば再ビルドは不要。
3. 現在のデータ形式を旧版が読めるか確認する。必要なバックアップ・変換を検討してから進める。
4. 同じApple Account・Bundle IDのまま、SideStoreで旧IPAを上書きする。アプリを削除することを標準手順にしない。
5. 起動と保存データの読み取りを確認する。

ソースを戻すときも、mainの履歴を消すforce pushを標準にしない。過去タグからの修正やrevertコミットで戻した経緯を残す。

## データの互換性

Gitでソースを戻せることと、iPhone内のデータを以前へ戻せることは別。現在のアプリはschema 1のみを受け付け、未知の保存形式を勝手に上書きしない。将来schemaを変えた場合、旧版ではそのデータを読めない可能性がある。

ユーザーの最新方針は、アプリ機能だけを更新・巻き戻し、ブックマークや履歴は常に端末内の最新状態を保持すること。共通形式schema 1を固定し、旧版→新版→旧版→新版の読み書きテストを配信前に行う。追加機能の設定等は共通JSONから分離する。古いバックアップを自動復元しない。署名更新はSideStoreが行うため、保存済みの未署名IPAが7日で使えなくなるわけではない。

## 自動配信への移行

2026-10-24の追加要件により、mainへのアプリ関連pushからビルド・Release保存・SideStoreソース更新を自動化する。タグは`vVERSION-build.NUMBER`。本体ソースは非公開を維持し、IPA・配信JSON・必要なアイコンのみ専用の公開リポジトリへ配信する。[初回設定と運用](distribution.ja.md)を参照。

# 0.15 写真保存・購入遷移・ページ保持・ライブのタブ一覧

- 写真保存: WebKit標準の「写真に保存」が写真ライブラリへアクセスする際に必要なNSPhotoLibraryAddUsageDescriptionと、旧方式用のNSPhotoLibraryUsageDescriptionを追加。画像の長押しで標準メニューを抑止していた処理も修正し、WebKitが渡す保存アクションを使う。写真の読取り処理や自動権限許可は追加しない。OSの許可・拒否を尊重する。
- 購入遷移: 通常のWebリンクをキャンセルしてURLから読み込み直す処理を廃止。元のWebKitナビゲーションと、WebKitが渡す別窓の構成を使い、Cookie、window.opener、継承されたsessionStorage、名前付きウィンドウ、POSTを保つ。明示した対応アプリ優先設定は残す。証明書の検証・例外範囲は変えず、購入POSTを自動で再送しない。
- 入力後の誤警告: 入力前のロック・信頼・origin・frame・document・formの検査は維持。入力成功の応答後に、サイトのフォーカス移動やフォーム更新を「入力失敗」に変換しない。秘密値を返す読取り操作の後検査は維持する。キャンセル済みのUIへ遅れた入力エラーを出さない。InputEventとchangeをcomposedで通知し、フォーカスのメタデータを即時更新する。サイト自身の本物の入力エラーは隠さない。
- ページ保持: 専用UserDefaults設定で標準12ページ、8～24ページを指定可能。旧features.jsonの形式は変更しない。従来の上限ちょうどでも1枚休止する不具合を修正。メモリ警告時は4ページを目標とし、再生・ダウンロード・読込み・入力中・購入POST・別窓の参照元を保護する。入力検出は信頼されたイベントから「編集済み」の真偽値だけを受け取り、値や項目名を収集しない。保管庫の入力成功も保持対象にする。iOSによるWeb処理終了やアプリ終了後まで生きたDOMを保証しない。
- タブ一覧: シートを使わず、ブラウザ内の一覧へ遷移する。1つの永続キャンバスに各WKWebViewを残し、一覧のカード位置へクリップと等比変形で移す。WebViewのviewportは一覧のためにリサイズせず、実際のページ・動画を表示する。選択中と表示中の再生ページをライブ表示し、他のカードは従来の保存済み画像を利用する。ホームの入口だけは現在表示している自前UIの一時スナップショットを使い、ディスクへ保存しない。動画にtakeSnapshotは呼ばず、既存のbuild14メディアスクリプト・音声セッションは変更しない。回転・スクロールの位置更新はUIKit内で直接行う。

共通のbrowser.json schema1、ライブラリ・保管庫・署名識別子・WebKitデータストアの保存形式は変更しない。既存の最新ブックマークや履歴へ古いバックアップを戻さない。

検証はCore、写真保存の実メニュー、Cookie/別窓/POST/8ページ後のDOM保持、実動画の一覧カード内の画素進行と戻った後の再生継続、既存の回転・タブ削除、保管庫のフォーカス移動、Releaseでのページ/キーボード操作を対象とする。テスト補助はDEBUGかつ--ui-testingと専用フラグの両方でのみ有効。eplusの実際の会員アカウント・決済・チケット購入はこの再現テストに含まない。

# 0.8.0：選択テキストをWeb検索

Webページ内の文字列を選択すると「自作ブラウザで検索」から検索結果を新しいタブへ開ける。元タブのすぐ右隣に追加し、元タブやCookieを削除しない。プライベートタブからはプライベートの新規タブにする。

WKWebViewのサブクラスで公開APIのbuildMenuを使い、標準メニューへ項目を追加する。superのメニューを残して追加するため、コピー・共有・調べるを置き換えない。WebKitがサブクラスのメニューを採用しない選択状況もあるため、文字列選択中だけページ右上にも同名の検索ボタンを表示する。メニューに出ない場合はこちらを使う。パスワード入力欄は読み取らない。PDF等、WebKitがDOMの文字列選択を公開しない表示では、コピーまたは共有してショートカットから検索できる。

検索エンジンは従来の「設定 → 検索エンジン」で変更する。新規インストール時はGoogle。保存済みのGoogle／DuckDuckGo／Bingの選択は変更しない。URLのような選択文字列も検索語として扱う。

mybrowser://open?url= の外部URL受信を維持し、mybrowser://search?text= を追加する。後者は共有されたテキストを設定中のエンジンで検索する。既存のonOpenURLとタブ処理を使い、未起動・バックグラウンドでも同じ入口で受信する。[ショートカットの設定手順](shortcuts.ja.md)。

URLComponents／URLQueryItemを使い、各階層で一度だけエンコード・デコードする。日本語・改行・絵文字・プラス記号・パーセント表記を保持する。検索語は前後の空白を除きUTF-8で16,384バイトまで。超えた場合は切り捨てず案内する。外部スキームは262,144バイトまで受信するが、iOS／ショートカットや検索サービス側にも長さの上限がある。

選択文字列はWebView内の一時状態で、ページ移動・WebView解放時に消去する。選択しただけで検索サービスへ送信せず、検索操作の時だけ送信する。既存のBundle ID、保存場所、schema1、タブ・履歴・ブックマーク・Cookie、既存設定の形式を維持する。追加Entitlementや拡張は使わない。

検証はエンコード・入力検証・既存設定保持のCore検査、実際のWebView選択→新規タブの代表ケース、既存の外部URL受信の代表ケースに絞る。初期値を変更したModels.swiftについては既存の互換性検査も実施する。標準メニューの表示可否や各サイト固有の選択挙動はiPhoneでの確認範囲とする。

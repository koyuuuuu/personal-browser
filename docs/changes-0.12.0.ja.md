# 0.12.0 下部のパスワード候補と任意の自動入力

ログインフォームを検出すると、ページ下部に「Appleのパスワード」とブラウザ専用保管庫への入口を表示します。保管庫の解除中は一致するサイトのユーザー名が候補として並び、タップで入力できます。管理画面を閉じた後も、設定した自動ロック時間までは解除状態を維持します。バックグラウンドと「今すぐロック」では即時にロックします。ロック中は「ブラウザの保管庫で入力」から端末認証を行い、一致が1件なら入力し、複数なら候補を選びます。歯車から従来の管理・取り込み・編集画面を開けます。

Appleに保存したアカウント一覧をアプリ独自の候補へ読み出す機能はありません。「Appleのパスワード」は公開APIで実際のWebフォームへフォーカスを移し、iOS標準のキーボード候補／鍵のボタンへ進む入口です。利用者がそこでアカウントを選択し、iOSが要求する認証を行います。Apple側の候補・認証をアプリから強制表示／省略する機能ではありません。

「設定 → 一般 → 自動入力とパスワード」で自動入力とAppleのパスワードを有効にしてください。候補が出ない場合はWebのユーザー名／パスワード欄を直接タップし、キーボード上の鍵から選びます。サイトのフォーム構造・端末設定・OS側の判断によっては候補が出ない場合があります。

「設定 → パスワード」に次の設定を追加しました。

- 「Appleの自動入力の認識を補助」（初期オン）：ログインフォームの不足したautocomplete属性をusername／current-passwordで補助します。new-password・one-time-code等の明示指定は変更せず、複数のパスワード欄は補助しません。オフでこの機能が付けた属性だけを可能な範囲で戻し、次のページでもオフを維持します。
- 「保管庫の解除中は確認なしで自動入力」（初期オフ）：ブラウザ保管庫に完全一致するアカウントが1件、対象フォームも1件のときだけ入力します。通常タブ・メインフレーム・未入力・利用者が未編集・信頼できるHTTPSという条件を満たす場合に限ります。保管庫を勝手に解除せず、Appleの認証も省略せず、ログインの送信もしません。ページ／フォームごとに1回だけ試み、失敗時に再認証や連続再試行を行いません。
- 「ログインフォームに下部候補を表示」：従来の入力ボタン表示設定を下部候補バーへ適用します。候補バーの×でその画面の候補を閉じることもできます。

ユーザー名だけを先に入力する段階は、autocomplete=usernameと明示された欄に対応します。この段階ではユーザー名だけを送り、パスワードをWebの入力処理へ渡しません。検索・一般のメールアドレス欄を一律にログイン欄とは扱いません。ブラウザ保管庫の自動入力では入力済み・ユーザー編集済みの内容を上書きしません。明示的に候補を選択する場合は選んだアカウントの内容を入力します。

既存のタブ・履歴・ブックマーク・Cookie・暗号化保管庫と鍵・バックアップ形式は変更しません。追加の有料EntitlementやAssociated Domains、パスワードプロバイダー拡張、非公開APIは利用しません。0.11.0 build65とすべての過去版を保持します。

参考：Appleの[HTMLフォームの自動入力指定](https://developer.apple.com/documentation/security/enabling-password-autofill-on-an-html-input-element)、[自動入力の処理と認証](https://developer.apple.com/documentation/security/about-the-password-autofill-workflow)、[WKWebViewによる資格情報の処理](https://developer.apple.com/documentation/authenticationservices/password-use-in-web-browsers)。

検証は既存の保管庫UI代表1件を拡張し、下部候補の選択入力、公開APIでのWeb欄フォーカスと属性補助、解除中の自動入力・非送信・手入力の保持・ユーザー名だけの段階を確認します。CIの端末にはAppleの実アカウントや保存パスワードを登録せず、Appleの候補内容・Face ID・iCloudキーチェーンの実機動作を確認済みとは扱いません。従来の暗号化・インポート試験に、未解除・複数候補・別ポート・プライベート・サブフレーム・編集済み等の自動入力拒否条件を追加します。
